# Refactoring CDaRR_git to a Functional Programming Standard

*Plan written 2026-07-15, after a file-by-file read of the whole repo (excluding `paper/`).*

The single most important constraint, stated up front: **every number this repo has
produced must still come out of the refactored code.** The paper results (exp1–exp5,
`compare_crr`, the composite figures) were generated by this exact code with these exact
seeds. The refactor is therefore organised around an equivalence-test harness that is
built *first*, against the current code, and must keep passing at every phase. Style
improvements never outrank bit-reproducibility; any transformation that changes a single
float is out of scope for the refactor proper (it can be a separate, explicitly-labelled
change later).

---

## 1. What "functional programming standard" means here

The same conventions already used in the sibling `CDaRR_FP` project (`cd/`, `cr/`,
`crr/`, `cns/` packages, pure functions, frozen dataclasses, pytest), applied to this
repo without changing its numerics:

1. **Pure decision logic.** Conflict detection, resolution, and recovery become pure
   functions: outputs depend only on their arguments. No `self.*` mutation, no reading
   `bs.traf`, no writing attributes onto other objects.
2. **Explicit, immutable state.** The recovery bookkeeping that today lives in mutable
   class attributes (`reso.resopairs`, `reso._intr_init_vel`) becomes a frozen
   `CdarrState` dataclass that is threaded through calls and *returned*, never mutated.
3. **Side effects only in the shell.** BlueSky (`bs.traf`, `bs.sim.step`, `bs.stack`),
   file I/O, and plotting live in a thin imperative shell. The functional core never
   imports `bluesky` except for its pure math helpers (`bluesky.tools.geo`,
   `bluesky.tools.aero.nm/kts`), which are deterministic functions of their inputs.
4. **Explicit randomness.** Every random draw takes a `np.random.Generator` argument.
   No `np.random.*` module-level calls (one legacy exception documented in §8).
5. **No hidden parameter channels.** Today the sim loop smuggles `sigma_r`, `sigma_v`,
   and `dcpa_prob_threshold` to the probabilistic recovery by assigning attributes onto
   the *detection* object. These become ordinary function parameters.
6. **Injected impurity.** The two genuinely impure recovery actions — `bs.traf.id2idx`
   lookup and the waypoint `route.direct` command — are injected as callables (exactly
   the `CDaRR_FP` `crr/common.py` pattern), so the decision logic stays testable without
   a live simulator.

### 2.2 Critical behavioral facts the refactor must preserve

These were verified by reading the code; each gets a dedicated regression test (§6).

* **F1 — Order of operations per ASAS tick:** `detect(observed)` → `detect(GT)` →
  `resolve(...)` → *assign sigma_r/sigma_v/threshold onto conf_detection* →
  `recovery(...)` → `pairwise.step(reso)`. `resolve()` returns `self.resopairs` **by
  reference**; the recovery step then mutates that same set in place (`update` with new
  confpairs, `-=` delpairs). So the membership test in `_do_action` sees the
  **post-recovery** pair set of the same tick. In the FP version: avoidance status =
  resopairs *after* the recovery transition.
* **F2 — Between ASAS events** (every `simdt` sub-step), the *stale* `reso` tuple is
  re-applied by `_do_action`. The shell must cache the last command.
* **F3 — Avoidance status semantics:** an aircraft is "avoiding" iff its ID appears in
  any pair of `resopairs` (either position; both aircraft of a pair maneuver). Non-
  avoiding aircraft are commanded their *nominal* (initial) heading/speed by the env —
  not their current one. The `cdarr` function itself (per the target spec, §4) returns
  current speed/heading for non-avoiding aircraft plus the status flag; the env shell
  keeps the nominal-restore behavior, driven by the flag exactly as today.
* **F4 — Recovery's other side effects are no-ops here:** `apply_recovery` sets
  `reso.active[idx]` (never read by `_do_action`) and calls
  `bs.traf.ap.route[idx].direct(...)` only when a route has an active waypoint —
  aircraft in this env are created with `bs.traf.cre/creconfs` and have no route, so
  `findact` returns −1 and nothing happens. (Phase 0's bit-equality goldens would catch
  this assumption being wrong.)
* **F5 — Desired-velocity lookup chain** in recovery (`get_desired_ownship_velocity`):
  `seltrk` → `ap.trk` → `trk`, and `selspd` → `ap.tas` → `gs` → hypot(gseast, gsnorth).
  The observed ownship is an `ADSLMessage`, which has no `seltrk`/`selspd` but carries a
  **shared reference to the live `bs.traf.ap`** — so the chain resolves to the
  autopilot's commanded track/speed. In the FP core this becomes an explicit
  `desired_trk`/`desired_gs` input; the shell extracts it with the *same* fallback chain.
* **F6 — VO quirk:** `VO.resolve` calls `self.resumenav(...)` (past-CPA criterion)
  internally at the end of every resolve, and the loop *also* calls the configured
  recovery afterwards. With `sim_config_vo.json` the pair set is therefore processed
  twice per tick. Preserve as-is (a `vo` composition step), do not "fix".
* **F7 — MVP small numerics:** `dv_mvp[2] = 0.5 * dv_mvp[2]` before both the subtract
  and the (conditional) noreso add-back; `resooffac`/`noresoac` are Entity traffic
  arrays that are all-False in this pipeline but are still *indexed* — the FP version
  takes them as optional all-False boolean arrays. Keep formula forms verbatim,
  including `(np.arctan2(newv[0,:], newv[1,:]) * 180 / np.pi) % 360` (do **not**
  rewrite as `np.degrees`), the `threshold = 0.001` dcpa floor, and the
  `rpz < dist and dabsH < dist` erratum branch.
* **F8 — Detection numerics:** keep `np.asmatrix`-based `kwikqdrdist_matrix` call,
  `1e9 * I` diagonal masking, `dv2` floor at `1e-6`, `tinhor/touthor` sentinels
  `1e8/-1e8`, and the side outputs `tcpa_all`/`tinhor_all` (the GT done-check uses
  them).
* **F9 — RNG streams actually consumed** (see the ledger in §5.2): only two streams
  matter per run — `seed+2` (ownship ADSL: reception draw *then* position noise *then*
  velocity noise, in that order, every ASAS tick after the first) and `seed+999`
  (intruder reception). Streams `seed+1/+3/+4` are constructed but never drawn from;
  `seed+7919` is the scenario RNG in the randomized/dist variants. The FP design keeps
  the same named streams and the same per-tick draw order/counts.
* **F10 — First-tick asymmetry:** the initialization block does a *full* ownship update
  (no reception draw) plus latency-bias application to all aircraft; the first in-loop
  event tick then draws reception + noise again. Latency bias is intruder-only and only
  re-applied to freshly-received indices (my-observation.md #13).
* **F11 — `_compute_ipr`** truncates the distance history to `nb_pair` columns, takes
  the min over time, counts `min < horizontal_sep`. `run_multiple_jobs` re-aggregates
  LOS counts with the fixed `NB_PAIR = 100` constant regardless of the env's actual
  pair count. Keep both, including the constant.

Core data types (all `@dataclass(frozen=True)`, arrays treated as immutable by
convention — never written after construction):

```python
class TrafficView:      # observed arrays aligned by index
    lat, lon, alt, gs, trk, vs, gseast, gsnorth: np.ndarray
    ids: tuple[str, ...]

class ConflictData:     # = today's StateBased outputs
    confpairs: tuple[tuple[str, str], ...]        # directed, both (a,b) and (b,a)
    qdr, dist, dcpa, tcpa, tlos: np.ndarray       # per confpair
    inconf: np.ndarray                            # per aircraft, bool
    rpz, hpz: np.ndarray; dtlookahead: np.ndarray
    tcpa_all, tinhor_all: np.ndarray              # full matrices (GT done-check)

class ResolutionCommand:
    trk, gs_capped, vs_capped, alt: np.ndarray    # per aircraft (vs/alt kept for completeness)

class CdarrState:
    resopairs: frozenset[tuple[str, str]]         # directed tuples, as today
    intruder_init_vel: Mapping[tuple[str, str], tuple[float, float]]

class CdarrParams:
    rpz, hpz, dtlookahead, resofach, resofacv: float
    resolution: Literal["MVP", "VO"]
    recovery: Literal["CPA", "FTR", "Probabilistic FTR"]
    gamma: float | None
    sigma_r, sigma_v: float | np.ndarray | None   # probabilistic worldview (exp5 mismatch supported)
    ktheta: int = 256
```

Design rules carried over from CDaRR_FP: recovery's impure hooks (`id2idx`, waypoint
recover) are injected with defaults that read BlueSky, and pure-null defaults in tests;
`RecoveryState` replaces the mutable `resopairs`/`_intr_init_vel` pair, with transitions
`new_state = replace(state, ...)`.

## 4. The `cdarr()` function

The three stages stay **separate, individually-importable pure functions** —
`cd.statebased.detect`, `cr.mvp.resolve` / `cr.vo.resolve`, `crr.<model>.step` — and
`cdarr()` is their composition, reproducing exactly the per-tick order F1:

```python
def cdarr(own: TrafficView,
          intr: TrafficView,
          desired_trk: np.ndarray,        # deg  — autopilot/nominal track  (F5 chain, extracted by shell)
          desired_gs: np.ndarray,         # m/s
          perf: PerfLimits,               # vmin/vmax/vsmin/vsmax arrays
          state: CdarrState,
          params: CdarrParams,
          hooks: RecoveryHooks = NULL_HOOKS,
          ) -> CdarrResult:
    conflicts = cd.statebased.detect(own, intr, params.rpz, params.hpz, params.dtlookahead)
    command   = cr.resolve(params.resolution, conflicts, own, intr, perf, params.resofach)
    decision, new_state = crr.step(params.recovery, conflicts, own, intr,
                                   desired_trk, desired_gs, state, params, hooks)
    avoiding  = membership_flags(own.ids, new_state.resopairs)        # F3, post-recovery (F1)
    gs_cmd  = np.where(avoiding, command.gs_capped, own.gs)           # non-avoiding: current speed
    trk_cmd = np.where(avoiding, command.trk,       own.trk)          # non-avoiding: current heading
    return CdarrResult(gs_cmd=gs_cmd, trk_cmd=trk_cmd, avoiding=avoiding,
                       state=new_state, conflicts=conflicts, command=command)
```

And the single-traffic-set convenience wrapper requested — *all* aircraft positions and
velocities in, per-aircraft speed/heading/avoidance-status arrays out:

```python
def cdarr_step(lat, lon, alt, gs, trk, vs, ids, state, params,
               desired_trk=None, desired_gs=None, perf=None,
               ) -> tuple[np.ndarray, np.ndarray, np.ndarray, CdarrState]:
    """own == intr == the one traffic set (every aircraft observes every other;
    the n x n detection with a masked diagonal already supports this — it is the
    same own==intr call the GT detector makes today).
    Returns (gs_cmd, trk_cmd, avoiding, new_state); for avoiding[i] == False,
    gs_cmd[i] == gs[i] and trk_cmd[i] == trk[i] (pass-through)."""
    view = make_view(lat, lon, alt, gs, trk, vs, ids)
    r = cdarr(view, view,
              desired_trk if desired_trk is not None else trk,
              desired_gs  if desired_gs  is not None else gs,
              perf or UNBOUNDED_PERF, state, params)
    return r.gs_cmd, r.trk_cmd, r.avoiding, r.state
```

Semantics pinned down:

* **avoiding[i]** ⇔ `ids[i]` appears in ≥1 pair of the post-recovery `resopairs` (F1+F3).
  Both members of a pair are avoiding (cooperative resolution, as today).
* For avoiding aircraft, `trk_cmd`/`gs_cmd` are the MVP/VO outputs after the
  vmin/vmax cap — bit-identical to today's `newtrack`/`newgscapped` at those indices.
* For non-avoiding aircraft the arrays pass through the *current* gs/trk (the user-facing
  contract). This differs from the raw `resolve()` outputs at those indices (arctan2
  reconstruction), but those entries were never consumed (§2.1) — consumed-output
  equivalence is unaffected. The env shell keeps restoring *nominal* speed/heading for
  non-avoiding aircraft, exactly as `_do_action` does today, using the `avoiding` flag as
  the membership test (same truth value as `any(id in pair for pair in resopairs)`).
* The two-view form (`own` = self-measured, `intr` = received/held messages) is what the
  stochastic sim uses; `cdarr_step` is the clean single-set entry point for future work
  (and matches the GT `detect(states, states, ...)` usage pattern).
* Recovery state (`CdarrState`) is the caller's to thread: `state = r.state` each tick.
  Fresh conflicts enter `resopairs` inside the recovery transition (as today), so a
  newly-detected pair is avoiding on the same tick it is first resolved.
* Statelessness of stages: `detect` and `resolve` are memoryless; only recovery carries
  state. `sigma_r/sigma_v/gamma` arrive via `CdarrParams` — no attribute-smuggling.

## 5. Reproducibility contract

### 5.1 Definition of "the result stays the same"

* **Reference:** the current code at the Phase 0 freeze commit, run in the `cdarr` conda
  env (numpy 2.3.5, scipy 1.17.1, joblib 1.5.3, shapely 2.1.2) with the BlueSky fork at
  `/Users/mfrahman/Projects/bluesky` (record its commit hash in
  `test/golden/ENVIRONMENT.md` during Phase 0, plus `conda env export`).
* **Equivalence level:** bit-identical (`np.array_equal`, `==` for scalars) on the same
  machine + env for: the per-tick consumed outputs (`trk_cmd`, `gs_cmd`, avoidance
  membership), full `distance_array` traces, `ipr`, `sim_timer`, `n_active`, and every
  aggregate in `run_multiple_jobs`' result dict. Fallback tolerance `atol=0, rtol=1e-12`
  is permitted **only** with a written justification in the test (none is currently
  expected: same expressions + same draw order ⇒ same bits).
* **Old-vs-new, not vs committed files:** several committed `results/*.json` predate
  recent model changes (the latency model was updated after `exp3.npz`/`exp4.npz`; the
  `_latency.npz` files are authoritative). The gate is therefore: *the refactored code
  reproduces what the frozen current code produces*, verified pairwise in the same env.
  Optionally, as a final sanity step, regenerate one committed cell known to be current
  (e.g. an `exp3_latency.npz` slice) and diff.
* **Parallelism invariance:** results must be independent of `n_jobs` (they are today:
  each rep is seeded `base_seed + rep` and joblib returns in submission order) — tested
  explicitly.

### 5.2 RNG ledger (the exact draw order the FP code must reproduce)

Streams per `get_ipr_stochastic_env(seed=s)` run:

| Stream | Seed | Consumed by | When |
|---|---|---|---|
| ownship ADSL | `s+2` | reception mask, position noise, velocity noise | every ASAS tick |
| intruder reception | `s+999` | Bernoulli reception mask | every ASAS tick |
| bus / intruder-noise / prev | `s+1`, `s+3`, `s+4` | **never drawn** (constructed only) | — |
| scenario (randomized/dist variants) | `s+7919` | speeds/dpsi/dcpa at env creation | once |
| experiment pre-draws (exp3–exp5) | `BASE_SEED=42` module-level `default_rng` | `dpsi_values`, `speed_own_kts`, `speed_int_kts` blocks, in that order | once per script |

Per-tick draw order on stream `s+2` (order and **count** both matter):

```
init tick   : [no reception draw]                                # first_update_done=False
              pos-noise draw(n)  -> vel-noise multivariate_normal(size=n)
every event : reception rng.random(n)                            # even at p=1.0
              pos-noise draw(n)  -> vel-noise multivariate_normal(size=n)
```

Position-noise draw shape per model (from `noise_distributions.py`; each model consumes
a *different* number of variates — swapping models changes the stream, which is why the
draws must stay inside the same functions):

| model | draws per call |
|---|---|
| default Gaussian (`pos_dist=None`) | `multivariate_normal(2x2 cov, size=n)` |
| `gaussian` | `standard_normal((n, 2))` |
| `make_mixture_gaussian` | `random(n)` + `standard_normal((n, 2))` |
| `make_anisotropic_gaussian` | `standard_normal(n)` + `standard_normal(n)` |
| `make_anisotropic_mixture_gaussian` | `random(n)` + `standard_normal(n)` + `standard_normal(n)` |

Rules derived from this ledger:

* Keep `default_rng(seed+k)` construction for all six named streams even where unused
  (cheap, and guards against accidental re-numbering).
* Keep `multivariate_normal` calls as `multivariate_normal` (its SVD path consumes the
  stream differently than `standard_normal @ chol` would — no "equivalent" rewrites).
* Keep the reception draw at `p=1.0` (it looks redundant; it advances the stream).
* Keep the bisection caches in the mixture/aniso factories (`_sigma1`, `_sigma_cross`)
  — deterministic, but they define the exact sigma values used.

### 5.3 Numerical discipline

* Port formulas by *moving text*, not re-deriving: same operation order, same constants
  (`2.448`, `111_320.0`, `6371000.0` vs `6371000.`, `1e9`, `1e8`, `1e-6`, `0.001`,
  `eps = np.finfo(float).eps * 100`), same `np.asmatrix` usage in detection.
* The event scheduler (`next_event_t`, `missed` catch-up arithmetic) and the done-latch
  (`done_with_timeout`, `_check_tcpa_tinhor_per_pair`) move verbatim into the shell.
* BlueSky fork untouched (M600 `MAX_TR/MAX_DTR2`, `creconfs`, `creconfs_dist`,
  `kwikqdrdist_matrix` all live there).
* No dtype changes, no `float32`, no reordering of accumulations (`dv[idx1] -= dv_mvp`
  loop order follows `conf.confpairs` order, which follows `np.where(swconfl)` row-major
  order — preserved by construction).

## 6. The equivalence test set

New directory `test/equivalence/` (pytest; add `pytest.ini` with markers `fast`,
`slow`, `golden`). Everything runs under `conda activate cdarr` (CLAUDE.md rule). The
harness has four layers plus determinism guards. **Phase 0 builds it against the old
code alone** (capture + self-consistency); later phases add the new implementation as
the comparison target.

### 6.0 Golden capture tooling (`test/golden/`)

* `capture_goldens.py` — runs the frozen code over the L2 config matrix (below) and
  writes one `.npz` per case: `distance_array`, `ipr`, `sim_timer`, `n_active`, plus a
  per-tick command trace (`trk_cmd`, `gs_cmd`, sorted resopairs-as-ids) recorded by
  thin wrappers around `resolve`/recovery. Also writes `ENVIRONMENT.md` (conda export,
  BlueSky fork commit, machine info).
* `capture_fixtures.py` — instruments one run per scenario family and pickles the
  *inputs and outputs* of `detect`, `resolve`, and each recovery at three chosen ticks
  (first-conflict tick, mid-resolution tick, release tick). ADSL messages are flattened
  to plain array dicts so fixtures are dependency-free. These feed L1.

### L0 — pure-math equivalence (fast, no BlueSky)

`test_equiv_prob_math.py`
: fuzz 1,000 seeded random geometries: `crr.prob_math.{Phi, _to_cov, _regularize_spd,
  log_p_theta_projected_normal, analytical_dcpa_prob_gt, analytical_past_cpa_prob}` vs
  the originals in `sim_models/crr_resumenav_probabilistic_ftr.py` — exact equality.
  Include the harsh regimes: high SNR (|mu|/sigma ≫ 1), near-zero `b`, `x=0`,
  `Ktheta ∈ {248, 256}`.

`test_equiv_dcpa_helper.py`
: `calculate_dcpa` (ftr) and MVP's inner-loop dcpa math against old, fuzzed, incl.
  `dv2 < 1e-6` floor and `dabsH <= 0.001` branch.

`test_equiv_noise_distributions.py`
: for each factory and `ci95 ∈ {3, 10, 15}`: same-seeded `Generator` into old and new →
  identical arrays; identical draw *counts* (compare `bit_generator.state` after);
  bisection sigmas equal to 16 significant digits.

`test_equiv_noise_model.py`
: `add_position_noise` / `add_velocity_noise` / `add_latency_bias` old-vs-new on
  synthetic states (the `plot_noise_models.py` `_DummyStates` trick), all 6 noise
  configs, `idx` full/partial/empty — identical output arrays and identical final RNG
  state.

## 7. Migration plan (phases with hard gates)

**Phase 0 — freeze & harness (no production code changes).**
Tag the current commit (`pre-fp-refactor`). Write `test/golden/` tooling, capture
goldens + fixtures, write ENVIRONMENT.md, land the L0 self-tests (old-vs-old) and
determinism guards. *Gate: goldens reproduce twice in a row; determinism tests pass.*

**Phase 1 — in-place extraction (behavior-preserving).**
Inside the existing files, split class methods into module-level pure helpers the
classes delegate to (detection geometry, MVP inner math already partially separate,
recovery criteria — completing what `crr_recovery_base.py` started). No caller changes.
*Gate: full L2 goldens bit-equal.*

**Phase 2 — the FP packages.**
Create `cd/`, `cr/`, `crr/`, `cns/` with frozen dataclasses and pure functions, porting
the Phase-1 helpers verbatim. Old classes remain the live path. *Gate: L0 fuzz + L1
fixture equivalence green for every module.*

**Phase 3 — `cdarr()` and the functional shell.**
Implement `cdarr/core.py` (composition, F1 ordering, F3 flags) and a new
`sim/pairwise_stochastic/loop.py` shell: BlueSky env stepping, ADSL/cns message flow
(same four-node topology, same streams per §5.2), event scheduler, done-latch, command
cache (F2), nominal-restore via `avoiding`. *Gate: shadow-mode test green on cases 1–8;
new-loop L2 green old-vs-new.*

**Phase 4 — switchover.**
`get_ipr_stochastic_env`, `_randomized`, `_dist` become thin wrappers over the new shell
with **unchanged signatures and defaults** — `experiments/*`, `compare_crr/*`,
`quick_test_ipr.py` need zero edits (keep the module-level `bs.init` guard: joblib
workers rely on import-time init). *Gate: full L2 + L3 + invariance suite green.*

**Phase 5 — cleanup & deprecation.**
Move `cr_mvp.py`, `cr_vo.py`, `crr_*`, `cd_statebased.py`, `adsl_*`, `noise_model.py`,
`reception_model.py`, `cns_adsl.py` to `legacy/` with import shims that `raise
ImportError("moved; see refactor_fp.md")` (or forward, during a grace window). Port the
ad-hoc tests to pytest. Fix the `envs` import-time JSON read (lazy, path-anchored).
Retire the L2 *command-trace* assertions (keep distance/ipr goldens forever as the
regression floor). Update README/CLAUDE.md. *Gate: whole suite green from a clean
checkout; optional: regenerate one current-results cell and diff.*

Each phase is a separate PR/commit series; the suite must be green before the next
phase starts. If any phase turns up a genuine bug whose fix would change results, the
fix is **deferred and logged** (like my-observation.md #13 was handled deliberately) —
first reproduce, then improve.

## 8. Risks and gotchas

| Risk | Mitigation |
|---|---|
| BlueSky global singleton (`bs.traf`, settings) leaks state between runs | shell owns all `bs` contact; determinism/run-order tests pin reset sufficiency |
| `Entity.settrafarrays` magic sizes `noresoac/resooffac/active` in old classes | FP takes them as explicit all-False arrays sized `ntraf`; L1 fixtures confirm |
| `ADSLMessage.perf/ap/selalt` are live shared references into `bs.traf` (F5) | shell extracts `desired_trk/gs` + perf limits per tick and passes arrays into the core |
| A noise model swap changes RNG consumption counts (§5.2 table) | draws stay inside `cns.noise`/`cns.distributions` functions moved verbatim; L0 checks final generator state |
| `np.asmatrix` deprecation pressure during the port | keep as-is; env is pinned; revisit only after the refactor, behind the same test suite |
| joblib workers re-import modules (macOS spawn) | keep import-time `bs.init` guard; keep `__main__` guards (the composite scripts show why) |
| Stale committed results tempt "regression vs files" testing | contract §5.1: old-vs-new of current code is the gate |
| `test_stochastic_sim_single_job_deterministic.py` already broken import | fix/retire in Phase 5; not a refactor regression |
| Temptation to unify MVP/VO post-processing "while we're here" | shared `cr/common.py` is allowed only because both files contain today the *identical* block — moved verbatim, L1 proves it |
